## The task

Write independent test vectors for every formula in `modules/debt/credit-cards/compute.js` (the "Credit cards" page: How much of your card limits you use, what paying the minimum really costs, and whether a balance transfer helps).

1. List every formula and rule the compute applies, including the ones it imports from `core/math/` and its tables. For each one, cite where it comes from (the README's source, or the official one if the README has none).
2. For each formula, work out by hand at least three cases: an ordinary one, a boundary (zero, a threshold exactly, the first and last year, a leap day, a negative or empty input) and a large or unusual one. Show the arithmetic in a short comment above each assertion, so a reader can check it without running code.
3. Write them as `node:test` cases appended to `modules/debt/credit-cards/module.test.mjs`, using small invented plans built in the test (see the existing tests for the shape). Compare money to the cent with a tolerance helper, not exact floats.
4. If your hand result disagrees with what the code returns, do not change the expected value to match: keep your value, mark the test `{ todo: "disagrees with compute: <why>" }`, and put the disagreements first in your answer with your reasoning. Those are the valuable part.

## How to answer

1. Start with a rationale of at most ten lines: what you changed and why.
2. Give the changes as unified diffs that apply with `git apply` from the repo root (`a/` and `b/` prefixes, three lines of context). Give a new file, or one you rewrote by more than half, whole instead (see below).
3. A whole file goes in its own fenced code block whose first line is a comment with its path (`// path: modules/x/y/compute.js`).
4. End with the list of files you touched and the commands that verify them (`npm test`, `npm run check`).

Rules:
- Follow the project's rules in `AGENTS.md`: `compute.js` stays pure (no DOM, fetch, storage or timers); money math lives in code, never in an AI model; plain words on screen; every formula gets a test and a written source.
- Never edit `modules/registry.js` (generated by `npm run registry`), `data/` or `planner.properties`.
- Tests use `node:test` and `node:assert/strict`, in the module's `module.test.mjs` or `tests/<topic>.test.mjs`, so that `npm test` and `npm run check` stay green. Say which commands you ran; if you could not run them, say so plainly.
- Every number needs a source (IRS/SSA/CMS publication, statute, paper, or a worked example you show). Put the source next to the number in a comment and in the module README.
- The repo is public: use invented example data only (no real names, addresses, account numbers).
- If something is unclear, state your assumption and carry on; do not stop to ask.
