## Builder's choices

1. **Filled = what a person sees**: the accent's fill after the cascade, chips excluded, in both checks. The spec's list
   also excluded `small`; `base.css` fills a small button with the accent, so it counts (no page has one on a first view
   today: no count moved).
2. **Real selectors are opt-in** (`fullSelectors()`), so the stand-in stays exactly as it was for the other 28 test
   files; the first-view lib turns them on for its own process.
3. **Taps aim like a person**: the shell's tap guard (`core/taps.js`, wave 1) swallows a second tap on the same spot just
   after the screen changed. The check taps each row at least 60 px from the last tap (left of the row, else its middle),
   waits for the section's own `toggle`, and retries once if the sandbox's `window.__swallowed` shows a swallow.
4. **A shut at the end of a page is not a move**: shutting a section can leave the page shorter than its scroll, and the
   browser pulls it back; the check does not count that (the open tap is always measured).
5. **Stored keys**: R16 and R31 say every key but `planner.more` stays identical; wave 1 records opened sections in
   `planner.place` (and `planner.trail`, `planner.nav`) by design (spec 3.11), so those are excluded too. The plan and
   every other key are compared byte for byte.
6. **The headline in a browser**: the page's first `h1`, else its first tile. **A way to start on the empty plan**: a
   filled button wholly on the first screen.
7. **The first-screen budgets**: words and figures only for answer pages (110, 8), as R1's last column; the rest of that
   column are structure checks (headline, filled button, first card, Save) per kind.
8. **S11**: a page that imports the helper must have a test named "S11" in its `module.test.mjs` (the spec: "the shard
   checks that the test exists").
9. **`--write` refuses a partial browser run** (fewer than four households, or `--quick`), and a rewrite exits 0 once the
   counts are written down. `--from run.json` judges or writes a saved run without measuring again.
10. **`shot --more` opens every section**, not only what the switches open (the task's words), after putting
    `more=all` in the address (the spec's); today no page has parts, so opening every `<details>` is what shows "all".

## What it cannot see

Meaning: a page can meet every number and still fold the wrong thing or use a word a layperson does not know; the
never-folded list and the 390 px screenshot stay read by eye (AGENTS.md rule 13). Node cannot see layout (where things
land, what is wide, what a tap moves), the shell around the page, or what needs a browser's own features (speech input);
it judges the first view only. The browser check sees layout but only for four households, only Chromium (no Safari, no
VoiceOver, no real thumb, no keyboard open), only pages in each household's menu (9 usable pages are in none: the four AI
helper pages, Audit, Backups, Diagnostics, Docs, Statements; Node covers them), and the memory round trip only once a page
has a reading part. Neither checks find-in-page or print. The path's Next is measured only where the step applies to the
household (18 drawings).
