## API as built (`core/ui/more.js`)

```js
import { part, parts, rest, choice, links, statusOf, detail, kept, forgetAll, openAll } from "../../../core/ui/more.js";
```

- `part(ctx, { id, kind, title?, n?, noun?, one?, says?, set?, guess?, missing?, fix?, open?, holds?, card?, lazy?, body })` -> `<details class="fold" data-part data-kind>`; `card: true` -> `card fold fold-card`. Markup exactly as spec 3.3 (summary `display:block`, inner flex row, `.fold-title`, a space, `.fold-status` only when there is one, `.fold-chev` aria-hidden; body `.fold-body` grid gap 12px).
- Open or shut, 3.4's order: reason now (`open: true`, `fix > 0`, `?show=` by id or `holds` once per route object, a capture `invalid` the kit answered) -> `kept` (kinds more/how) -> `detail.working` (kinds more/how) -> shut. Guide `opens:`, wave 1 typing, find-in-page and print open by script and are never kept (a trusted click on the summary only, read one tick later).
- `parts(ctx, ...list)` -> `<section class="card" data-parts><div class="folds">` rows, order more, own/figures, how, item, tech (stable inside a kind), falsy skipped, `null` when empty, throws in a test above 5.
- `rest(ctx, { id, items, row, first = 6, noun, one?, keep?, list = "records", card? })` -> `[ul]` or `[ul, part]`; never hides fewer than 3 rows; `keep(item, i)` rows stay among those shown, in place; lazy above 40 hidden rows; `row(item, index)`.
- `choice(ctx, { id, label, presets, value, own: { type: money|percent|number, label, min?, max?, whole?, show?, name? }, onPick })` -> `div[data-choice] > div.chips[role=group] + holder`; chips are `button.chip` with `aria-pressed`; "Yours: 5.5%" (percent), "Yours: $1,250" (money, `ctx.fmt.money`) when the plan's value is none of the presets; "Type my own" (`aria-expanded`) builds the kit's `moneyBox` / `numberBox` on tap and removes it on a second tap; `onPick` on a chip tap or the box's `change` after the kit's check; a chip already on does nothing; focus goes into the box only from the keyboard.
- `links(ctx, [{ href, ask, says? }])` -> `section.card[data-links] > h2 "More on this" + ul.page-list > li > a.row-link` (`.t` the question, `.d` the answer, a muted chevron); with `ctx.route.query.guide` set, one shut `part` of kind `links` (`card: true`) holding the same list; `null` when empty; throws in a test above 5.
- `statusOf({ says, set, guess, missing, fix })` -> the person's state first (`N to fix` > `not set yet` > `set by you` / `N set by you` > `our guess` / `N our guesses`), then ` · says` only when the whole fits 20 characters; never cut.
- `detail`: `init(ui)` (keeps the kit, calls `ui.setMoreOpen(detail.boxes)`), `working`, `boxes` (stored or `?more=` for the visit), `chosen` (stored only), `forVisit`, `set({ working?, boxes? })` (stores only when on; a `working` change either way forgets the 0 marks; `boxes` calls `setMoreOpen` at once).
- `kept`: `get(page, id)` (refreshes the day at most once a day), `set(page, id, open, designed)` (stores only what differs from `designed`), `count()` (the 1 marks), `clear("open" | "shut" | "all")` -> how many went.
- `forgetAll()` (Erase the copy on this device: switches and parts, key removed, kit told), `openAll(root)` -> `shutAgain()` (print; also usable by C2's same-markup check).
- Constants: `MORE_KEY` (`planner.more`, `planner.more.sandbox` with `?sandbox`), `KEEP_DAYS = 90`, `KEPT_KINDS = WORKING_KINDS = ["more", "how"]`, `KINDS`, `TITLES`, `STATUS_MAX = 20`, `MAX_PARTS = 5`, `MAX_LINKS = 5`, `FIRST_ROWS = 6`, `MAX_ENTRIES = 300`; `_test.reset()`, `_test.clock(fn)` for tests.
- Key format: `{ fmt: 1, working?: 1, boxes?: 1, parts: { "group/id#part": [1|0, day] } }`; removed when nothing is stored; entries 90 days unseen dropped on read (and written back); not `fmt: 1` reads as nothing and is overwritten; storage that throws keeps a copy in memory.

## Choices where the spec was unclear (the builder's)

1. **Status order when both fit**: "1 set by you · 2026" (the person's state first, R25 read literally), not the
   prototype's "2026 · 1 set by you".
2. **`set: true`** means a part with one figure: "set by you"; a number gives "N set by you". `guess: true` = 1.
3. **"1 more ..."** needs `one` ("number"): `noun` is the plural; a test refuses n = 1 without it (R14 says such a part
   should rarely exist).
4. **In a test, a broken rule throws** (no id, an unknown kind, an item/tech without a title, a "more" part without n and
   noun, a sixth part, a sixth link); in a browser it warns and draws. "In a test" = no real document (the same test as
   the kit's `DOC`).
5. **The `invalid` listener opens the part only when the form kit answered** (`defaultPrevented`), or when the kit is
   not on the page: `checkValidity()` fires `invalid` too, and a silent live check must not pop a part open. The kit
   already opens every shut section around a reported box (`bringTo`), so the listener mostly builds a lazy body.
6. **A landing scrolls only on a new arrival** (the page at its top when the part is drawn): on Back, Forward or a
   reload the part is open and wave 1's spot wins. It scrolls with `ui.reveal(el, { block: "start" })`, which does
   nothing for a part already wholly on screen (measured: the part stayed at 342 px, focus on it). The spec's "68 px from
   the top" holds when the part is below the screen.
7. **`?show=` once per route object, as specified**: on the redraw after a save the landed part is no longer forced
   open; if the save was inside it, the page's `pending` keeps it open (R17). A save in *another* part shuts the landed
   one (wave 1 carries only tapped sections). If C3 finds that wrong, the alternative is one line: keep the landing for
   every draw of the same route object (wave 1 then carries a person's shut on its own).
8. **The `designed` state used for storing** is the switch as it is this visit (`?more=` included): what the page drew
   without the tap.
9. **Extra exports** beyond 3.2: `forgetAll()` (C7's "Erase the copy on this device"), `openAll(root)` (print and C2's
   S13), `detail.chosen` (what Settings' two boxes show, apart from `?more=`), `KINDS`, `MAX_LINKS`, `_test`.
10. **`choice()` and R32**: the helper draws no box of its own; "Type my own" builds the kit's `moneyBox`/`numberBox`
    for a figure of the plan, only after the tap. The "no input" test covers the first draw.
11. **The 3.11 agreement cases** need wave 1's DOM-side code, which the repo's fake DOM cannot run (it has no
    `Element` prototype getters or selector lists); the test defines a small standards-shaped DOM of its own (prototype
    getters, the selector subset `core/place.js` uses) and runs the real `start`, `foldsOf`, `applyFolds` and
    `inShutFold`. The "types in a box" row is checked through `inShutFold` as `refill()` uses it, not the whole typing
    store.
12. **The template's import is right where it lives** (`../../core/ui/more.js`, as its `module.test.mjs` already does),
    with a comment giving the path once copied (`../../../core/ui/more.js`). The first try used the after-copy path and
    `tests/static-host.test.mjs` (every relative address the app loads must exist, GitHub Pages is strict) failed on it;
    `tests/more.test.mjs` imports the template directly and checks both paths are written in it.
13. **No claim row**: C1 touches no page (`modules/_template` is not one).
