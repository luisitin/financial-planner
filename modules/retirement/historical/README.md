# If history repeated  (`retirement/historical`)

**Status:** usable (phase 5); `heavy: true`
**Purpose:** Your plan replayed from every start year since 1928 with the real returns and inflation of those years.

## Inputs
The projection inputs; `data/returns.js` (generated by `tools/extract-history.py` from `vendor/data/damodaran-histretSP.xls`: S&P 500 with dividends, 10-year Treasuries, 3-month bills, CPI, 1928-2025). `params.quick` skips the safe-spending search.

## Outputs
`windows`, `successRate`, `runs[]` per start year (success, failYear, failAge, endReal, minReal), `worst[]` (5), `best[]` (3), `medianEndReal`, `safeSpending` (the fixed-real spending that survived the six hardest starts), `dataRange`, `verdict`.

## Formulas
Only start years with enough years of data for the whole plan (`RETURNS.length - years + 1` windows). Cash earns the bill rate of each year; inflation is that year's CPI change. Safe spending: bisection (`affordableSpending`) over the six worst starts, minimum of those.

## No Social Security in the plan (2026-11-01)
When an adult has no Social Security figure and has not said they get none (`overview/setup` `ssMissingFor`, the same check as the
Dashboard's "Retirement: Needs Social Security"), the page opens with a notice from `modules/retirement/ss-notice.js`: "Social
Security is not counted yet, so this page looks worse than it is", a filled "Add Social Security" and an outlined "We won't get
Social Security", which saves the setup's own `guide.setup.ss[personId] = "none"` so it is never asked again. Before, only a
grey sentence at the end of a paragraph said why the plan looked short.
