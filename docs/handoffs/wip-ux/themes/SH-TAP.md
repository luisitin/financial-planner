(b) 'Changes saved.' and then an empty 'Add an expense' form opens by itself (x6-expenses-first.png); with the thumb 20 px higher it opened 'Edit Daycare' instead (x5-save2-cashflow-expenses.png), a different expense with the same boxes. A double tap on a list row lands inside the form that scrolled up (How often, By when, Retirement age), opening a picker.
- should: The second tap of a double tap does nothing unless it lands on the same control as the first. After a save the person stays where they were with the confirmation in view.
- why: Reproduced 20+ times at 150 to 500 ms gaps, with real touch events at one fixed spot, and at 4x CPU slowdown. - fix: One change in the shell (core/app.js, next to mendBlockedForms): remember the last tap (target, x, y, time) in a capture-phase click listener; swallow (preventDefault + stopPropagation, also on touchend so no box is focused and no picker opens) any tap that comes within about 450 ms and 40 px of the last one and whose target is not the same element (or inside it). - why: A layperson taps a page name, sees nothing happen for one to four seconds, taps again, and is thrown to the Dashboard. No pressed state, no closing menu, no 'working' words: it reads as a dead control or a crash.
- cause: core/app.js show(): line 236 `ctx.derived = safeCompute(m, ctx.plan)` runs the page's whole calculation with default settings before the page draws anything, and 153 of the 161 page views never read ctx.derived (8 mention it). (3) While a heavy page is being worked out set #content and #sidebar inert (or pointer-events: none) and clear it when the render resolves, so a second tap is dropped. Later: run the heavy compute in slices the way careful.js whenWorked already does. No design-log decision is touched.
