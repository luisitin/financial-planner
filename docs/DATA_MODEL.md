# Data model: the plan object

One JSON object. The executable definition is `core/schema/migrate.js` (`emptyPlan()`);
this page explains each section and who owns it. "Owner" is the module that defines the
shape and is the first place to look for its fields.

Common conventions: every list item has an `id` (uid), dates are `YYYY-MM-DD`, money is a
number in `meta.currency`, rates are fractions (0.07), people are referenced by `personId`.

## Rules for changing it
* New optional field on an existing item: just read it with a default. No version bump.
* New section: add to `emptyPlan()`; `migrate()` back-fills missing sections automatically.
* Renamed / re-shaped field: bump `SCHEMA_VERSION`, add `migrations[n]`, never edit an old migration.
* Document here in the same change.

## Where it is stored
* PC server: `data/plan.json` (+ `data/backups/plan-<timestamp>.json`, last 50 by default).
* Each browser: `localStorage["planner.plan"]` as an offline copy / the only copy when no server.
* Sandbox: `localStorage["planner.plan.sandbox"]` when the app is opened with `?sandbox=1`; a
  pretend plan that is never sent to the server (testers and demos; `docs/TEAM.md` rule 6).
* Export / import: System > Settings, plain JSON.

## Not in the plan (device or server side)
* `localStorage["planner.plan.demo.family"]`, `["planner.plan.demo.couple"]`, `["planner.plan.demo.starter"]` -- a pretend
  family's plan while someone looks around (`?sandbox=1&demo=<name>`, core/demo/README.md). Made from the plans bundled in
  `core/demo/`, never from the real plan; never sent to the computer; erased by "Leave". Adds no field to the plan.
  Each has a mark `<key>.made` = `{ day, rev }` (the day the copy was made and its stamp then: an untouched copy is made
  again on a later day, a changed one after 30 days). `sessionStorage["planner.demo.left"]`: a note "Leave" writes for
  the next page ("Pretend family closed"), removed when read.
* `localStorage["planner.connection"]` -- server URL, token, this device's AI settings.
* `localStorage["planner.features"]` -- this device's page toggles.
* `localStorage["planner.view"]` -- "build" when this device shows the build view (core/view.js); absent: the household's view.
* `localStorage["planner.nav"]` -- the menu's open topics and recent pages on this device (core/app.js).
* `localStorage["planner.more"]` (`planner.more.sandbox` in the sandbox) -- how much this phone shows
  (core/ui/more.js, docs/OPTIONAL.md): the two switches of Settings > How much to show, and the reading parts a person
  opened or shut by hand, by page and part name with the day each was last drawn (forgotten after 90 days unseen, at
  most 300). Never a figure, a name or anything from an account; never sent to the computer, never in a downloaded copy.
  Settings' "Erase the copy on this device" removes it (the sandbox's own key in the sandbox); "Shut them all" forgets
  the rows a person opened.
* `localStorage["planner.look"]` (`planner.look.sandbox` in the sandbox) -- how this phone looks (core/look.js;
  Settings > Screen, and the menu's "Hide amounts"): `{ fmt: 1, hide?: 1, text?: "larger" | "largest", theme?: "light" |
  "dark" }`. `hide`: every money amount drawn on screen reads "$•••" (the plan, `money()` and a printout are untouched).
  `text`: the base text at 17 or 19 px instead of 15 (`<html data-text>`). `theme`: light or dark whatever the phone asks
  (`<html data-theme>`). index.html reads the last two before the first paint. Absent: the app looks as it always did. No figure, no
  name; never sent to the computer, never in a downloaded copy. Settings' "Erase the copy on this device" removes it.
* `sessionStorage["planner.typing"]`, `["planner.place"]`, `["planner.trail"]` (each `.sandbox` in the sandbox) -- this
  tab only (core/place.js, core/router.js): typing not saved yet (a day at most), the spot and open sections of each
  history entry, and the way each entry was reached.
* `planner.properties` -- the server's settings (never inside the plan, never served).
